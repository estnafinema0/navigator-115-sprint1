### Дополнение 27.10: форма заявления под новый контракт API документов (коммит eac0664)

- Запрос документа: `{values, scenario, first_level_done}`; `scenario` из разбора, `first_level_done` = `true`, если на шаге «Сроки и маршрут» отмечено «Банк уже рассмотрел мои документы», иначе `null` (не указано). В пустом шаблоне `first_level_done` не передаётся.
- Ошибки 409/422 показываются рядом с кнопкой документа: «Документ не собран.» + `detail.message` и, если есть, «Последний день срока банка по календарю: дд.мм.гггг». Предупреждения из `X-Navigator-Warnings` выводятся текстами из `GET /api/v1/documents/codes` в рамке «Документ собран, проверьте перед отправкой». Английских кодов на экране нет (проверено регулярным выражением по тексту списка документов).
- Поля: ручное поле «Дата, когда истёк срок банка» убрано (срок считает сервер, `X-Review-Due-Date`); добавлено «Дата ответа банка на ваши документы» (только для отказа в операции и в открытии счёта); «Дата, когда вы представили документы в банк» подставляется из шага «Сроки».
- Пустой шаблон: № 4, № 5 и «Обращение в Банк России» по-прежнему скачиваются с `values: {}` (ответ 200, предупреждения о пустых датах в пустом шаблоне не показываются). Напоминание `reminder_13_4` с пустыми `values` сервер не собирает (422 `docs_submitted_date_missing`), поэтому для него уходит одна дата представления документов, без реквизитов; если срок не истёк, честный отказ 409 с датой. Это сказано в тексте «Где ваши данные».
- Детектор обхода: в ответе `/api/v1/parse` есть только `meta.injection_detected` (уже показывается в карточке); признака намерения обхода в `parse` нет, `/api/v1/intent` в вебе не вызывается (поля для вопроса пользователя нет). Веб не менялся.
- Проверка (A1, первый уровень отмечен, документы представлены 26.10.2026, API в режиме правил): № 5 и напоминание: «Документ не собран…», последний день срока банка 05.11.2026; № 4: собран с предупреждением «Дата отказа не указана…»; пустые № 4, № 5, обращение скачиваются.
